# Assisted-CAD Modeling Method

Working notes from the assisted-CAD modeling session so far:

- **Declare the canonical axes before modeling:** for this bookcase, use **X = width, Y = depth, Z = height**.
- The model must stand naturally upright and grow toward **+Z**.
- The lower corner of the first sketch must be at the origin.
- Every accepted sketch must be parametric, explicitly dimensioned with driving dimensions, and fully constrained/locked before modeling proceeds; a locked sketch without explicit driving dimensions is not sufficient.
- **Hard sketch-closure gate:** reject a sketch before extrusion unless it is both dimensionally specified and geometrically closed in a robust sense. For a rectangle built from primitive lines, endpoint coincidence alone is insufficient; required relationships such as perpendicularity and parallelism must also be explicitly present so the profile is fully specified, not merely visually closed. Grounding at the origin is allowed, but extrusion must not proceed until this closure/specification gate passes; any violation is a hard failure, not a warning or an item to defer.
- A sketch is not acceptable merely because its final bounding box is correct: it must also lie on the correct functional face or surface for the part being modeled.
- **Bounding-box and sketch-semantic correctness are orthogonal requirements:** both must pass independently. Do not choose between a correct bounding box and correct sketch semantics; a part fails if either one is wrong.
- **Canonical sketch-plane selection rule:** when choosing a sketch plane, first choose the plane that yields the simplest planar geometry for the sketch; if multiple planes give equally simple geometry, choose the one corresponding to the largest functional surface area. This rule is intended to prevent accidental edge/thickness/cut-section sketches for board-like parts and should be checked together with final bounding-box validation.
- **Non-orthogonal surface rule:** when surfaces intersect non-orthogonally, always create and use a construction plane aligned to the intended geometry instead of forcing a base plane. In the current Billy bookcase, the bottom and toe-kick rails are normal to the side panels, but this rule is broader and applies to non-orthogonal furniture such as corner bookcases.
- For a board-like part, a valid sketch must be the functional silhouette-bearing face of that part. Reject sketches that are merely edge, thickness, or cut-section profiles, even if their dimensions or bounding boxes happen to come out right.
- Before proceeding, verify both the final bounding box and the sketch semantics. Keep the sketch count minimal, but never at the cost of using the wrong face; reuse a sketch only for truly identical geometry.
- **Redundant-sketch prohibition:** sketch proliferation is forbidden. Before creating a new sketch, reason about whether the target geometry is symmetric, repeated, or shared with an existing functional silhouette. If so, reuse a generic reusable sketch and derive the second solid or feature through parameter-driven placement, mirroring, offset, pattern, or another reuse strategy. For symmetric panels such as bookcase sides, do not create duplicate side sketches; reuse the generic side-profile sketch. The same rule applies to identical front/rear elements: do not create separate sketches when one reusable profile is valid.
- **Sketch preflight is mandatory:** before creating any sketch, explicitly write down (1) the functional face/surface the sketch represents, (2) which part dimensions live in the sketch, (3) which dimension is extruded, (4) the expected final bounding box, and (5) how the sketch supports mirrored/opposite parts and cut-list/BOM usage. If all five points are not defined in advance, do not create the sketch.
- Create sketches directly in their final position. Never create geometry elsewhere and move the body afterward.
- Only assemblies/components may be repositioned; do not reposition an individual body as a fix or workaround.
- **Deterministic orientation rule:** orientation and sketch-plane selection must be treated as a deterministic verification problem, not guessed. Use explicit axis/vector checks or a calculator-like geometry-reasoning workflow to confirm the intended X/Y/Z mapping and growth direction; intuition or “looks right” is not evidence. If the environment lacks a dedicated calculator/geometry-reasoning tool, compensate with explicit preflight checks before creating the sketch.
- **Never assume sketch-local axes map intuitively to model axes.** In Fusion 360, a sketch on the **YZ plane** maps sketch local **Y** to model **+Y**, while sketch local **X** maps to model **−Z**. Therefore, dimension orientation and geometric constraints must follow the true local sketch axes, not the apparent model-axis names or screen orientation. For a **left side panel on the YZ functional face**, a model point at **Z = +1900** is represented by sketch coordinate **u = −1900** (with sketch Y representing model +Y); then extrude along model **+X** for thickness. Verify this mapping before applying dimensions, constraints, or extrusion; otherwise a visually plausible panel can have reversed height, misplaced edges, or incorrect semantics.
- **Use an explicit vertex map before creating geometry.** Record each intended model-space silhouette vertex and its corresponding sketch-space coordinates, including sign changes from the YZ mapping. If rectangle helpers introduce ambiguity about local orientation or corner order, build the silhouette from primitive sketch lines instead. Use parameter-driven dimensions and expressions rather than hardcoded numeric values. The final bbox gate for **Side_L** is **X = 0..18, Y = 0..280, Z = 0..1900**.
- **Fusion API units:** numeric API values are in **cm** unless an operation explicitly documents another unit. Convert the preflight dimensions and expected extents accordingly, and do not interpret raw API values as millimeters.
- **Mandatory deterministic orientation/sketch advisor rule:** invoking the deterministic orientation/sketch advisor is mandatory before creating any new sketch. Its verdict must be applied to the functional face actually being modeled, not to an adjacent reference face or an assumed equivalent. Use its verdict to guide Fusion execution, then confirm the result in Fusion with final bounding-box and scene validation. For simple extrusion-friendly parts, its input must describe the intended functional face, the dimensions in the sketch, the extruded dimension, the canonical axes, and the expected bounding box. If the verdict conflicts with the intended method, stop and resolve the plan before modeling. For board-like parts, the sketch plane should match the silhouette-bearing face and the extrusion axis should match the board thickness direction. Do not apply the advisor blindly to non-sketch-based CAD, such as OpenSCAD authoring.
- **Mandatory final gate:** validate the final bounding box and confirm that each sketch is on the correct functional face. Any orientation violation fails the gate and requires another iteration; do not continue with a known violation.
- **Final bounding-box validation remains mandatory after axis mapping checks.** Correct YZ mapping, dimensions, constraints, and extrusion direction do not replace validation of the resulting model-space extents; compare the final bbox against the preflight expectation before accepting the part.
- **Six-face reference/envelope rule:** once the artifact's bounding envelope is defined, reason explicitly about all six planar envelope faces rather than relying only on the three origin-adjacent faces. Construction planes and sketch references may be derived from the front or back, top or bottom, and left or right faces, using positive or negative offsets as appropriate. This reduces sign errors, preserves references, and makes rear rails and other back-mounted elements easier to place robustly. For a rear element, it may be preferable to create a construction plane on the rear face (or on a face coplanar with the side ends) and offset inward by the recess parameter instead of computing its position from the front/origin side.
- Do not proceed to mirrored or opposite parts until the base part passes every gate: correct sketch-plane semantics, a quoted and locked sketch with driving dimensions, deterministic orientation verification, and final bounding-box compliance. If any gate fails, rebuild or iterate the base part first; do not propagate the error.
- Side panels must not include toe-kick recesses; only toe-kick rails are recessed.
- **Face-mounted board rule:** for a toe-kick rail or other face-mounted board, place the sketch on the corresponding functional face plane (front or rear), and extrude it from the adjacent reference plane by a parameter-driven recess. Keep distinct parameters distinct: front and rear recesses must not be conflated merely because they currently share a value. When front and rear elements form a pair, model both elements even when one currently has an offset of zero; zero offset does not make the element optional.
- **Existing-body reference rule:** when modeling a cross/front panel that connects existing side bodies, take sketch references from those bodies and use the references as geometric constraints. Parameters declare metadata and intended customization points; they do not replace available body-derived references. Driven dimensions from the existing references are still required for the sketch to document and verify the resulting geometry.
- Sketch on the correct face/plane for the silhouette, not on the edge/thickness face; for board-like parts, the silhouette-bearing face is part of the sketch's semantics, not merely an orientation detail.
- Use history-based parametric expressions.
- **Parameter-usage rule:** every user-customizable dimension must be represented by a parameter, and every defined parameter must be consumed by the design. Avoid hardcoded numeric literals except for canonical, non-parameterized distances or constants. Do not introduce parameters merely to avoid a literal: avoid DRY violations and over-parameterization, and keep one source of truth for repeated geometry. When creating mirrored or opposite parts, placement offsets must also be driven by parameters rather than hardcoded values unless the geometry is correctly derived from existing references.
- Stop at HITL checkpoints when the method changes.
